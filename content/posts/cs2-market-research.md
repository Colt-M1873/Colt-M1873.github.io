## 研究方向一：价格动量与趋势

**核心问题**：哪些商品在过去 180 天涨幅/跌幅最大？价格趋势是否具有持续性（动量效应）？

**分析内容**：
- 全量 12,324 件商品的 180 天价格涨跌幅排行榜（TOP/BOTTOM 各 50）
- 按品类、品质、磨损分组的平均涨跌幅对比
- 价格趋势分段：上涨 / 下跌 / 震荡 / V 形反转 的商品数量分布
- 动量检验：过去 30 天涨幅最大的商品，未来 30 天是否继续上涨（用历史数据滚动验证）
- 价格均值回归检验：偏离 90 天均值超过 30% 的商品，后续是否回归

**关键数据**：`sell_min_price_history`，全量 12,324 件，3,474 个时间点  
**技术难点**：需要对每件商品构建时间序列，内存需分批处理（建议每批 500 件）  
**预期产出**：`price_momentum_report.md`  
**已生成报告**：[price_momentum_report.md](/research/price_momentum/)

## 研究方向二：流动性评分体系

**核心问题**：如何量化每件商品的流动性？哪些商品「高价值但难卖」，哪些「低价值但易套现」？

**分析内容**：
- 流动性评分模型（4 个维度加权）：
  - 在售量（权重 30%）：在售量越多，流动性越好
  - 价差率（权重 30%）：价差越小，流动性越好
  - 在售率（权重 20%）：在售量/存世量，比例越高流动性越好
  - 价格稳定性（权重 20%）：价格波动越小，流动性越好
- 各品类、品质、磨损的流动性评分分布
- 四象限分析：高价值高流动性 / 高价值低流动性 / 低价值高流动性 / 低价值低流动性
- 流动性最好/最差的 TOP 50 商品榜单

**关键数据**：`sell_min_price_history` + `sell_num_history` + `goods_existence_history`  
**技术难点**：评分模型需要归一化处理，存世量仅覆盖 5,912 件，需处理缺失值  
**预期产出**：`liquidity_score_report.md`  
**已生成报告**：[liquidity_score_report.md](/research/liquidity_score/)

## 执行建议

### 是否需要多 Agent 模式？

**结论：不建议使用多 Agent 并行模式。**

原因如下：

1. **机器资源限制**：当前环境为 2 核 2G 内存。每个研究脚本都需要连接同一个 1.4G 的 SQLite 数据库，多 Agent 并行会导致数据库锁竞争和内存溢出，反而比串行更慢甚至崩溃。

2. **数据库并发限制**：SQLite 不支持真正的并发写入，多进程同时读取大表（350 万行）会产生严重的 I/O 竞争。

3. **研究之间存在依赖**：方向二（流动性评分）依赖方向三（波动率）的结果；方向七（跨磨损套利）依赖方向六（StatTrak™ 溢价）的配对逻辑。串行执行可以复用中间结果。

4. **调试成本**：多 Agent 并行时，某个 Agent 的错误难以及时发现和修正，串行执行可以逐步验证每个报告的数据质量。

## 研究方向九：在售价、求购价与成交价三价关系（滑点研究）

**核心问题**：在售价、求购价和成交价之间的差额（滑点）有多大？滑点与时间、行情热度、品类、磨损、品质有何关系？买方还是卖方在主导成交价格？

**分析内容**：
- 三价定义：买卖价差率（Spread）= (在售价 - 求购价) / 在售价；滑点率（Slippage）= (成交价 - 在售价) / 在售价
- 成交价在买卖区间的位置分布：买方主导 / 中间成交 / 卖方主导 / 溢价成交
- 滑点率分布：负滑点（买方通过求购单成交）vs 正滑点（直接接受挂单价）
- 月度三价趋势：价差率与滑点率的时间变化，反映市场定价效率演变
- 按品类、品质、磨损分组的滑点率对比
- 价格区间 × 滑点：U 形关系验证（极低价和极高价滑点均大）
- 行情热度（在售量）× 滑点：流动性溢价效应量化
- 价差率与滑点率的 Spearman 相关（按品类）
- 负/正滑点极值 TOP 30 商品榜单

**关键数据**：`sell_min_price_history` + `buy_max_price_history` + `sell_price_history`，18,894 个三价对齐点位  
**技术难点**：`sell_price_history` 为最近一笔成交价（非当天均价），需按日期对齐三价后计算；成交价覆盖天数（45天）少于在售价（61天）  
**预期产出**：`slippage_report.md`  
**已生成报告**：[slippage_report.md](/research/slippage/)
